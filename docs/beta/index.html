Contribution instructions ↗
01 / PUBLISH A CAPABILITY

Useful work, with context.

Describe a skill or worker, version, provenance, usage terms, task scope, pricing when offered, and evidence you have permission to publish.

Use data records in a pull request. Contributed code is never run by the catalog.

Review the submission format ↗
02 / EVALUATE INDEPENDENTLY

Make the limitations visible.

A separate contributor records the method, sample, outcomes, failures, environment and disclosed conflicts. Different reviewed GitHub authors alone do not establish scientific or organizational independence. Evaluator-reported results remain distinct from maintainer reproduction.

A signature authenticates a key and payload. It does not prove a task succeeded or a person’s identity.

Submit an evaluation ↗
03 / BUILD ON WHAT CAME BEFORE

Improve it, preserve attribution.

Link an improvement to an earlier version and evidence hash. The public history keeps the chain inspectable.

Attribution metadata records credit and provenance. Legal ownership and permission still depend on applicable terms and law.
